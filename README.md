# Crocaun Android

Отдельный публичный Android-клиент проекта [crocaun](https://github.com/infsofit/crocaun). Цель — совместимость передачи файлов, чата и истории с Windows-клиентом; визуально копировать Windows-интерфейс не требуется.

### Что уже можно использовать

- **Передача Croc** — самостоятельный протокол, не чат. Используется Croc `v10.0.12` с Crocaun race-патчем; Go/AAR повторяет Windows password/relay mapping. Файлы копируются во внутренний staging перед отправкой. Выбор одиночных/нескольких файлов выполняется через SAF; каталоги можно выбирать через Document Provider или вводить абсолютный путь. Папка обходится рекурсивно, имена нормализуются и уникализируются для Windows, но Croc отправляет их отдельными файлами без исходной структуры вложенных папок.
- **Получение** — staging остаётся приватным, если папка назначения не настроена. Можно задать каталог через SAF-провайдер либо абсолютный системный путь; автоматическое сохранение не перезаписывает существующий файл и сохраняет структуру вложенных каталогов, если это поддерживает провайдер. При ошибке несохранённые staging-файлы остаются в списке для ручного экспорта. Общий путь Android может требовать отдельно разрешённого `MANAGE_EXTERNAL_STORAGE`; предпочтительный вариант — SAF.
- **ZIP** — по умолчанию распаковка выключена. При включении ZIP распаковываются в приватный staging-каталог; оригинальный архив остаётся доступным. Проверяются абсолютные пути и Zip Slip, исключается перезапись; действуют ограничения на число элементов и объём распакованных данных. Результат этой новой функции пока не прошёл проверку на устройствах.
- **LAN-чат** — использует TCP `29014`, ручное подключение по IP или поиск Windows-совместимым UDP `29015`. Поиск не заменяет Croc discovery на UDP `29008`. Для одной комнаты Android и Windows должны использовать одинаковый пароль. Интернет-чата в этом экране нет.
- История чата хранится в `files/chat-lan/history/` как JSONL из зашифрованных кадров. Пароли комнат не сохраняются: после перезапуска нужно повторно ввести пароль комнаты. Файловые предложения/загрузки чата используют отдельный LAN-протокол.
- В Settings реализована проверка доступности публичных Croc relay ping/pong. **Настройки прокси пока нет:** её добавим в общие настройки только вместе с реально подключённой маршрутизацией, а не как неработающий переключатель.

## Android и протоколы

- Kotlin, Jetpack Compose; минимальная версия Android 11 (API 30), compile/target SDK 36.
- LAN-чат повторяет Windows параметры PBKDF2-HMAC-SHA256, room ID, AES-256-GCM nonce/AAD и Base64 Raw Std; wire format — newline-delimited JSON (`hello`, `rooms`, `have`, `m`, `get`, `file`). Поиск устройств чата — UDP `29015`, Croc peer discovery — отдельный UDP `29008`.
- LAN TCP-транспорт чата не шифруется целиком: зашифрованы содержимое сообщений и кадры локальной истории, но служебные заголовки и вложения передаются без дополнительного транспортного шифрования. Не используйте LAN-чат в недоверенной сети.
- Для приложений с target SDK 37+ Android 17 требует runtime-разрешение `ACCESS_LOCAL_NETWORK`; добавить его до повышения target. См. [локальные сетевые разрешения Android](https://developer.android.com/privacy-and-security/local-network-permission) и [All files access](https://developer.android.com/training/data-storage/manage-all-files).

## Сборка

Нужны Go 1.26+, Android SDK и NDK `27.2.12479018`:

```bash
scripts/build-transfer-aar.sh
./gradlew --no-daemon --stacktrace testDebugUnitTest assembleDebug
```

Скрипт получает закреплённый upstream Croc v10.0.12, применяет Android-патчи, запускает Go-тесты, проверяет gomobile Java API и создаёт `app/libs/crocaun-transfer.aar`. `golang.org/x/mobile` закреплён в `go-core/go.mod`; gomobile требует `golang.org/x/mobile/bind` в графе зависимостей. GitHub Actions собирает AAR/APK и загружает их как временные artifacts при push/PR.

## Нумерация версий и публикация

Windows-релиз остаётся базой Android-нумерации. Синхронизированный релиз использует тот же номер (`v1.11` → `versionName` `1.11`). Между Windows-релизами разрешены уникальные Android prerelease-теги `vMAJOR.MINOR-android.N`, например `v1.11-android.1`; существующие релизы не перезаписываются. Android-only workflow требует совпадающую стабильную Windows-базу и подтверждение `interop_confirmed=true`. Не публиковать до прохождения interop gate выше. Релизный APK сейчас debug-подписан; постоянный signing key не настроен.

Подробнее — [дорожная карта релизов](docs/release-roadmap.md).
