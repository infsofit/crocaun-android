# Crocaun Android

Отдельный Android-клиент для проекта [crocaun](https://github.com/infsofit/crocaun). Цель — совместимая передача файлов и текста, чат и история; копировать интерфейс Windows-программы не требуется.

> **Состояние:** начальный Kotlin/Jetpack Compose-каркас. Передача данных, чат и история ещё не реализованы; APK на этом этапе нужен для проверки структуры проекта и CI.

![Оригинальная иконка Windows-программы Crocaun](assets/branding/crocau-windows-256.png)

## Android и технологии

- Kotlin с нативным Android UI на Jetpack Compose.
- Минимальная версия — Android 11 (API 30). Целевая и compile-версия — Android 16 (API 36).
- Первый модуль — `app`. Переносимое сетевое ядро планируется выделить отдельно и подключить как Go Android AAR после проверки его зависимостей и совместимости.
- Вкладки стартового каркаса: отправка, получение, чат, история и настройки.

## Сборка

В Android Studio откройте этот репозиторий и соберите `app` → `assembleDebug`. Из терминала:

```bash
./gradlew testDebugUnitTest assembleDebug
```

GitHub Actions собирает debug APK при push в `main`, pull request, ручном запуске и ежедневной проверке версии Windows. APK доступен в артефактах соответствующего workflow на 14 дней.

## Нумерация версий

Windows-релиз — источник номера Android-версии. CI читает последний публичный релиз из `infsofit/crocaun` и передаёт его номер в `versionName`; например, текущий Windows-релиз `v1.11` даёт Android `versionName` `1.11`. Для Android-релиза создаётся такой же тег (`v1.11`): workflow проверит наличие одноимённого Windows-релиза, соберёт APK и создаст GitHub prerelease. Тег следует ставить только после проверки совместимости Android-кода с соответствующей Windows-версией.

Android `versionCode` вычисляется отдельно и строго возрастает по компонентам версии: `major * 1_000_000 + minor * 1_000 + patch`. Например, `1.11` соответствует `1011000`, а `1.11.1` — `1011001`.

Автоматическое мгновенное событие из Windows-репозитория не настроено, чтобы не менять его workflow. Вместо этого Android CI ежедневно опрашивает публичный список релизов; Android prerelease публикуется только при создании совпадающего Android-тега.

GitHub prerelease пока содержит debug-подписанный APK для тестирования, а не production-сборку Google Play. Постоянный ключ подписи не создаётся и не хранится без отдельного решения владельца проекта.

## Лицензия

Лицензия Android-проекта ещё не выбрана. Репозиторий публичный, но для разрешения стороннего повторного использования нужно отдельно добавить лицензию после проверки прав на код и ресурсы.
