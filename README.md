# Crocaun Android

Отдельный Android-клиент для проекта [crocaun](https://github.com/infsofit/crocaun). Цель — совместимая передача файлов и текста, чат и история; копировать интерфейс Windows-программы не требуется.

> **Состояние:** реализован первый LAN-чат с совместимыми Windows параметрами шифрования, зашифрованной локальной историей и chat-вложениями. Основное Croc-ядро собрано в AAR в CI, а в Android добавлена начальная однофайловая Send/Receive-реализация с SAF и приватным staging. Реальную передачу Android↔Windows ещё нужно проверить; пока нет фоновой службы, отмены и прогресса по байтам, поэтому эту сборку нельзя считать проверенным функциональным релизом. Internet/Nostr-чат и автоматическое обнаружение устройств также не реализованы. APK остаётся debug-подписанным preview.

## Android и технологии

- Kotlin с нативным Android UI на Jetpack Compose.
- Минимальная версия — Android 11 (API 30). Целевая и compile-версия — Android 16 (API 36).
- LAN-чат подключается к Windows-клиенту по IP-адресу и TCP-порту `29014`. Для общего пароля комнаты используются те же PBKDF2-HMAC-SHA256 параметры, room ID, AES-256-GCM nonce/AAD и Base64 Raw Std формат, что и в Windows. Обмен — newline-delimited JSON с типами Windows `hello`, `rooms`, `have`, `m`, `get`, `file`.
- История чата хранится в app-private `files/chat-lan/history/` как JSONL из зашифрованных кадров. Пароли комнат на диск не записываются: после перезапуска нужно повторно ввести пароль комнаты, чтобы открыть её историю.
- Вложения чата выбираются и сохраняются через Android Storage Access Framework (`content://`). Чтобы Windows peer мог отдать вложение напрямую, исходник копируется в приватный каталог приложения, пока приложение запущено.
- Основная передача Croc в Windows использует Croc `v10.0.12` с Crocaun race-патчем. Это отдельный протокол от чата. `go-core/transfer` повторяет Windows password/relay mapping; AAR собирается и тестируется в CI, входит в APK и вызывается вне UI-потока. Текущие Android экраны поддерживают выбор одного файла, передачу через приватный staging и экспорт полученного файла через SAF. Передача ожидает живой Windows↔Android interop-проверки.

## Что поддерживается и чего пока нет

Можно вручную подключиться к Windows-узлу в доступной LAN/VPN, если TCP `29014` достижим с обеих сторон. Сообщения шифруются совместимым с Windows AES-GCM форматом. При одинаковом пароле комнаты Android и Windows вычисляют одинаковую комнату. Вложения чата предлагаются peer-у и скачиваются напрямую по TCP, как в Windows LAN chat.

Автоматический UDP discovery пока не подключён: в Android нужно ввести IP/порт собеседника. Интернет-чат через Nostr, Windows identity/signing key, NIP-01/BIP-340 и интернет-вложения ещё не реализованы. Croc Send/Receive пока ограничены базовым UI для файла, не переживают закрытие процесса, не поддерживают отмену и не показывают размер переданных данных. Перед использованием preview с важными данными нужно проверить на двух устройствах правильный/неправильный пароль, Unicode-имя, ошибку relay и отсутствие случайной перезаписи.

Обратите внимание: как и Windows LAN-chat, TCP-транспорт чата не шифрует соединение целиком. Тело сообщений и история зашифрованы, но служебные заголовки и LAN-вложения передаются без дополнительного транспортного шифрования. Не используйте этот режим для недоверенной сети.

## Сборка

Сначала соберите переносимое ядро: для этого нужны Go 1.26+, Android SDK и NDK `27.2.12479018`. Затем соберите и протестируйте APK в Android Studio или из терминала:

```bash
scripts/build-transfer-aar.sh
./gradlew testDebugUnitTest assembleDebug
```

Скрипт получает Croc v10.0.12 с закреплённого upstream commit, применяет Crocaun race-fix и Android-specific патчи, запускает Go-тесты, проверяет Java API и создаёт `app/libs/crocaun-transfer.aar`. `golang.org/x/mobile` намеренно закреплён в `go-core/go.mod`: gomobile требует, чтобы пакет `golang.org/x/mobile/bind` присутствовал в графе текущего модуля. Для Android привязки задан linker flag, документированный зависимостью `anet` для обхода Go 1.23+ проверки её `go:linkname`; локальное обнаружение при этом отключено в Croc options. Android-патчи запрещают вывод секрета в logcat и отключают ненужный startup DNS lookup, поскольку приложение явно задаёт relay. AAR включается в APK; GitHub Actions собирает и загружает AAR и APK как временные artifacts при push/PR.

Ежедневный запуск и ручной `workflow_dispatch` без Android-суффикса по-прежнему сверяют опубликованные стабильные Windows releases с исходным `appVersion`, создают отсутствующий Android-тег той же версии и публикуют prerelease с APK. Отдельный Android-only prerelease создаётся только при ручном запуске workflow с `android_version`, например `1.11-android.1`, и `interop_confirmed=true`. Workflow проверяет соответствующий стабильный Windows release и откажется повторно использовать существующий Android tag. Этот режим предназначен для выпуска Android-функций до следующего Windows-релиза и не изменяет Windows-репозиторий или его workflow. Не запускайте его до прохождения release gate в дорожной карте.

План этапов и условия готовности функциональных релизов находятся в [`docs/release-roadmap.md`](docs/release-roadmap.md).

## Нумерация версий

Windows-релиз остаётся базой Android-версии. Обычные синхронизированные Android-релизы используют тот же номер стабильного Windows-тега (`v1.11` → Android `versionName` `1.11`, тег `v1.11`). Между Windows-релизами разрешены отдельные Android prerelease-теги вида `vMAJOR.MINOR-android.N` или `vMAJOR.MINOR.PATCH-android.N`; например, `v1.11-android.1`, затем `v1.11-android.2`. Базовый Windows release должен существовать, быть стабильным и совпадать с `appVersion` в его исходнике. В GitHub Actions для такого релиза вводится `1.11-android.1` без начальной `v`; теги уникальны и не перезаписываются.

`versionCode` резервирует до 99 Android-only выпусков на одну Windows-базу и остаётся возрастающим при переходе к следующему numeric patch: `((major * 1_000_000 + minor * 1_000 + patch) * 100) + androidSerial`, где `androidSerial` равен 0 для обычной Windows-синхронизированной версии и 1–99 для `-android.N`. Например, `1.11` → `101100000`, `1.11-android.1` → `101100001`, а `1.11.1` → `101100100`.

GitHub prerelease содержит debug-подписанный APK для тестирования, а не production-сборку Google Play. Постоянный ключ подписи не создаётся и не хранится без отдельного решения владельца проекта.
