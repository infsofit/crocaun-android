# План функциональных Android-релизов Crocaun

Android-версия следует Windows-нумерации. Функциональность двигается отдельными этапами, но опубликованный Android prerelease создаётся только для стабильного Windows-тега с тем же номером и совпадающим `appVersion`. Поэтому номер следующего функционального релиза заранее не фиксируется. Если нужного Windows-релиза ещё нет, промежуточную сборку следует распространять как GitHub Actions artifact, а не создавать Android-only тег и не заменять существующий релиз.

## Текущее состояние — v1.11 preview

`v1.11` — ранний debug-signed preview с LAN-чатом, историей и chat-вложениями. Он не включает стандартный Croc send/receive, UDP discovery или Internet/Nostr chat. Эту уже опубликованную версию нельзя переиспользовать для другого содержимого APK.

## Этап 1 — переносимое ядро Croc

Подготовить Go AAR поверх Croc `v10.0.12`, повторить Windows Crocaun-вывод общего секрета и порядок relay, а также применить race-патч для передачи нескольких файлов. До UI-интеграции CI проверяет golden-тесты, собирает Android AAR и публикует его только как временный Actions artifact. Прежде чем переходить к интерфейсу, нужно проверить, что gomobile экспортирует ожидаемый API и что сборка надёжно повторяется.

## Этап 2 — базовая передача файлов

Добавить отдельные Send и Receive экраны для одного файла. Android SAF-выбранный файл копируется в app-private staging с сохранением исходного имени; входящий файл сначала принимается в отдельный staging-каталог, затем пользователь экспортирует его обратно через SAF. Первое функциональное preview разрешается выпускать только после успешной двусторонней проверки Windows↔Android: правильный и неправильный пароль, файл с Unicode-именем, ошибка relay и защита существующего файла от перезаписи. На этом этапе показываются стадия и ошибка передачи; основной экран не должен блокироваться.

## Этап 3 — надёжная длительная передача

Поддержать несколько файлов, пустые и вложенные каталоги, крупные файлы, повторное подключение и явные результаты передачи. Операция должна жить в foreground service, показывать реальный прогресс, предоставлять отмену и безопасно обрабатывать возврат в приложение и перезапуск процесса. Отмена и прогресс — release gates, а не обещание первого AAR: текущий Croc API синхронный и напрямую не предоставляет Android-friendly cancellation API. Проверить параллельные файлы, пробелы/Unicode в именах, неправильный пароль, отмену, частичный сбой и отсутствие случайной перезаписи на Windows и Android.

## Этап 4 — LAN-обнаружение и завершение базового чата

Реализовать UDP discovery на совместимых портах, UX соединения без ручного IP, устойчивое восстановление TCP-сессии и обработку конфликтов истории. Повторить матрицу Android↔Windows для комнат, сообщений, синхронизации истории и chat-вложений. Проверить разрешения Android 11+ и поведение в Wi-Fi, hotspot и VPN. LAN-вложения остаются отдельным протоколом от основной Croc-передачи.

## Этап 5 — Internet chat и расширенные возможности

Спроектировать отдельный Android backend, совместимый с Windows Nostr chat: ключи и identity, подписи, room/event mapping, history sync, статусы собеседников и Internet file hosting. Каждый протокольный элемент сначала сравнить с Windows implementation и проверить end-to-end на тестовых аккаунтах. До этого Android поддерживает только LAN-чат, и нельзя заявлять полную совместимость чата.

## Этап 6 — готовность стабильного распространения

До production-релиза определить владельца и лицензию, проверить лицензии зависимостей и иконки, согласовать хранение секретов и политику диагностики, подготовить release signing key и процедуру его восстановления, затем проверить release APK на чистой установке и обновлении. Debug-signed prerelease не следует представлять как Google Play build. Лицензия проекта пока намеренно не выбрана.

## Правило публикации

Каждый этап сначала проходит CI и проверку на реальных устройствах. Функция включается в публичные release notes только после прохождения её gate. Если Windows-версия с подходящим номером ещё не опубликована, сборка остаётся Actions artifact; нумерация Windows и уже опубликованные Android tags/releases не меняются.
